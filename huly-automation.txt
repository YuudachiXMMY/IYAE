Huly 自动化能力研究报告

平台已确认的自动化机制

基于 Phase 4B 实际发现 + 最新 Huly 文档：

机制 1：Action Item 自动状态推进（已可用）

这是 Huly 最核心的自动化：

┌───────────────────────────────────────┬─────────────────────────────────┐
│               用户动作                │            自动触发             │
├───────────────────────────────────────┼─────────────────────────────────┤
│ Issue 分配给某人 + 状态设为 Todo      │ 自动在该人 Planner 创建 Action  │
│                                       │ Item                            │
├───────────────────────────────────────┼─────────────────────────────────┤
│ 该人在 Planner 中安排(schedule)       │ Issue 状态自动从 Todo → In      │
│ Action Item                           │ Progress                        │
├───────────────────────────────────────┼─────────────────────────────────┤
│ 该人完成(check off) Action Item       │ Issue 状态自动 → Done           │
├───────────────────────────────────────┼─────────────────────────────────┤
│ Action Item 被取消                    │ Issue 回滚到上一状态            │
├───────────────────────────────────────┼─────────────────────────────────┤
│ Action Item 逾期未处理                │ 自动发送提醒                    │
└───────────────────────────────────────┴─────────────────────────────────┘

关键：这基于 Status
Category（Backlog/Active/Done/Cancelled），不是状态名。你自定义的状态名只要
Category 正确就能触发。

机制 2：Cards Process 转换触发器（已可用，Phase 4B 发现）

在 Card Type 的 Process 定义中，可配置的转换触发器：

┌──────────────────────────┬────────────────────────────┬─────────────────┐
│          触发器          │            说明            │     实用度      │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ On execution start       │ Process 开始时 →           │ ★★★★★           │
│                          │ 进入首状态                 │ 已验证可用      │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ On approved              │ 审批通过时                 │ ★★★★            │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ On rejected              │ 审批拒绝时                 │ ★★★★            │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ When action item done    │ 关联的 Action Item 完成时  │ ★★★★            │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ When action item         │ Action Item 取消时         │ ★★★             │
│ cancelled                │                            │                 │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ When card matches        │ Card 属性满足条件时        │ ★★★             │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ When field changes       │ 字段值变化时               │ ★★★★            │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ On sub processes done    │ 子流程全部完成时           │ ★★★             │
├──────────────────────────┼────────────────────────────┼─────────────────┤
│ Wait until               │ 等待到指定时间/条件        │ ★★★             │
└──────────────────────────┴────────────────────────────┴─────────────────┘

机制 3：Calendar 集成（已可用）

- Google Calendar 双向同步
- 在 Planner 拖拽 Issue 到日历时间块
- Focus time 时间块
- 共享日历、会议议程
- 重复任务（daily routines）

机制 4：GitHub 集成（已可用，Phase 4A 确认）

- Issue/PR 双向同步到 Clossette 项目
- PR 合并可关联 Issue 状态变更

机制 5：MCP Server（高级，可编程）

- 通过 API 程序化控制 Projects, Issues, Documents, Calendar Events
- 支持 stdio + HTTP 传输

---
关键约束（来自 Phase 4B 实际发现）

- 无手动推进触发器：状态推进必须通过自动化触发器（On approved
等），无法配置"用户手动点击推进"
- Process 状态不可筛选：Cards 的 Saved Views 无法按 Process 状态筛选（只能按
Card 属性筛选）
- 转换配置复杂：每条转换需要逐一配置触发器，不是简单的拖拽连线

建议：如果你想把这些自动化场景做成 Cowork 可执行的 Phase 文档，我可以创建
Phase 4F。但考虑到 Phase 4B 发现的限制（转换配置复杂），建议先在 Huly
中手动试配 1-2 个转换（比如 Document Approval 的 On
approved），确认实际效果后再批量配置。
